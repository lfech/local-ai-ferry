# Security

Report suspected vulnerabilities privately. In the GitHub repository's
**Security and quality** tab, use **Report a vulnerability** if available.
If private reporting is unavailable, ask the maintainers for a private channel
without including the vulnerability details in a public issue.
[GitHub private reporting guide](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)

Include the affected checkout revision, the commands or settings involved,
the potential impact, and a minimal reproduction using disposable data.
Remove credentials and private information before sharing logs or attachments.
For issues specific to upstream Open WebUI, Ollama or Docker, use the relevant
upstream project's reporting channel.

Backups may include chats, settings, workspaces and credentials. Treat them
as private and keep them out of version control.
[Backup contents and handling](docs/transfer.md#debian-backup)
